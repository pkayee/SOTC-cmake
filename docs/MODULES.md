## The XFF container
An `.XFF` file starts with the magic `xff2` and is a relocatable overlay: a header, `.text`/`.data`/`.rodata`, a relocation table and a footer. Overlays are linked at virtual address `0x40010000`. In this repository each module is linked as an ELF (`ET_REL` for the `.XFF` modules, `ET_EXEC` for `SCPS_150.97`: check with `readelf -h build/<M>/<M>.elf`), then `objcopy -O binary` + `tools/fix_xff.py` turn it into the XFF layout and restore the relocated operand words. `tools/parse_xff_relocs.py` reads the relocation records of an original XFF (R_MIPS_32/26/HI16/LO16 ...). A consequence: **the module SHA1 does not depend on whether a C function brings its own literals**, because `fix_xff.py` restores those words; literals are judged per function by objdiff ([MATCHING.md](MATCHING.md)).

Address rule when you load a built `.elf` of an `.XFF` module into Ghidra: every allocated section sits `+0x10000` above the address in `asm/` and the config files (`.text` 0x400405c0 in the config = 0x400505c0 in Ghidra's address space). `SCPS_150.97.elf` is not shifted. See [REA.md](REA.md).

## `config/<MODULE>/`
| file | purpose |
|---|---|
| `<MODULE>.yaml` | splat config: segments (`asm`/`c`/`data`/`rodata`/`bss`), per-segment compiler options (`"-O2 -G0 cc=..."`) |
| `<MODULE>_symbols.txt` | named symbols (`name = 0xADDR; // type:func size:0x..`) |
| `<MODULE>_relocs.txt` / `manual_rels.txt` | relocation overrides for splat |
| `<MODULE>_ignore_symbols.txt` | symbols splat must not emit |
| `undefined_syms.txt` | extern symbols for the linker (hand maintained) |
| `*_undefined_syms_auto.txt`, `*_undefined_funcs_auto.txt` | generated by splat, git-ignored, deleted before each configure |

## Chunks and rodata slices
`GAMECORE`, `MANAGER` and the six debug tools were a single asm `all_text` segment. They are cut into `c` chunks at real function starts (8-aligned, previous function ends in `jr`/`j`/`b`), roughly 3-12 KB each, named `chunk/cNNNN_<first function>` (`src/GAMECORE.XFF/chunk/c0000_ResetCharacterObj.c` ... 240 files). Each chunk also has a `.rodata` slice (`asm/<MODULE>/data/chunk/<chunk>.rodata.s`): the strings, jump tables and float constants its functions reference, so a function with literals can be matched. Procedure and caveats: [SPLITTING.md](SPLITTING.md).

## Scoring quirks you will meet
- Original objects name data by blob symbols (`%hi(D_40132C98)`); a C literal creates `[.rodata]+off`. Write the reference as `extern const f32 D_40132C98;` when scoring.
- Switch jump tables: `tools/jtblcheck` normalises a score to 100 only when every differing instruction is a table-address instruction and the tables have identical entries.
- Relocation order differs between splat's asm and gcc's output; `tools/relsort` stably sorts `SHT_REL` entries before objdiff (scoring-only; no bytes change).
